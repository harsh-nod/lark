# BMM and Linear recorded evidence

`ptx_extended_evidence.py` checks the already retained BMM and Linear proof
packets, anonymous publication observations, actual source CI responses and
completed non-force main-promotion receipts. Its authored
`ptx_extended_protocols.json` fixes the expected source identities, shapes,
limits, launch geometry, scope, counters and historical file bindings. The
reader uses the Python standard library and executes no captured program,
Lean proof, compiled object, model request or GPU trial.

These are two independent source-bound abstract PTX development proofs. They
add no original model pass rate, legacy registered profile, IEEE/error bound,
NVIDIA execution/conformance or original optimized-kernel result.

BMM's three cached development Main checks and its failed intermediate export
are kept distinct from the official source-only checks. Linear retains all
twelve earlier partial or library development attempts: seven accepted and
five failed. The first cold driver's original partial `running` label remains
raw historical data; the recorded terminal failure prevents counting it as
live or accepted. Failed compiler-recovery axiom output is never treated as
an accepted proof audit.

Every member of every archive is read and SHA256 checked, including all failed
history and compiled objects. Current and older official exports additionally
check complete inventories, fixed input/Main/source hashes, source-only module
rosters, copied module sources, checker commands, bounded completion, actual
axiom logs and reference ASTs. The three current replays bind the original
export and regenerated Main. Direct controls require a non-timeout Lean error
at the actual `source_program` theorem. Wheels must contain the same complete
owned source bytes and preserve the recorded older source pins.

The new reader has separately declared uncompressed bounds for its larger
recordings: 30 MB for complete official source archives, 45 MB for BMM history
and 225 MB for Linear history. The actual history sizes are 41,333,197 and
209,294,476 bytes. These do not change the earlier GEMM reader's 40 MB bound,
the 10,000,000-byte archive-member guard, proof or workload limits, or the
120-second replay / 300-second full control-suite / two-worker limits.

Publication checks require the full fixed file roster, exact published hashes,
successful anonymous TLS observations and the bound packet. CI checks require
the actual commit, run, distinct jobs and successful completion. Main receipts
must retain the expected metadata-only delta, source CI, successful guards and
non-force update. They explicitly record that the metadata-only promoted commit
did not receive a separate source CI run. Linear also binds the preceding BMM
main-promotion receipt.

The tests use actual copied packets outside Git and coherent mutations of
metadata, nested manifests, archive member inventories and outer packet hashes.
They include all eight scope controls for each new proof, nested axiom/AST/
module/budget attacks, failure-history preservation, wheel isolation, anonymous
TLS observations and main-promotion guards.

The default is now the v26 ledger containing these recorded packets. The
readers validate retained evidence and establish no full-paper completion.

The [pinned reader-validation receipt](snapshot-v26-ptx-reader-validation-v1/results.json)
records a complete standard-library-only run from isolated Python outside Git
and the checkout, with Git absent from `PATH` and no SDK import. Both complete
packets, all 16 archives and all 1,662 members passed. The subsequent complete
17-test reader/control suite passed in 56.167 seconds, including all sixteen
coherently rehashed scope controls. The complete driver, commands, stdout,
stderr, source hashes and result bindings are retained. No fresh Lean, GPU or
model experiment was performed, and the original v25 snapshot is unchanged.
